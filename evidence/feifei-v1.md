# 财经桌宠 PRD

版本：v0.2  
日期：2026-11-02（北京时间）  
状态：首版需求草案，供设计与开发使用  
产品名称：待定；本文使用“财经桌宠”作为工作名称。

## 1. 产品定义

一个可以从网页下载、常驻桌面的财经信息小猪。用户点击桌宠，先阅读简洁的摘要卡片；需要了解细节时，进入网页版查看完整简报、原始链接与历史内容。

产品每天整理午间和晚间的财经信息、股市动态，以及与市场相关的国内和国际新闻，让用户用几分钟掌握重点。所有发布的事实信息必须能够追溯到具体来源，并在发布前完成原文核对。

核心体验：**一只肥肥的小猪，每天给用户送来一份有依据、能点开原文的财经简报。**

## 3. 用户与使用场景

### 3.1 首批目标用户

希望了解市场、没有时间反复刷财经资讯的个人用户。用户可能拥有自选股，也可能只关心大盘、行业与重要新闻。

### 3.2 核心场景

1. **午间快速了解市场**：用户看到桌宠的更新提醒，点击后读取上午市场概况、热点变化和重要消息。
2. **晚间回顾与准备**：用户查看全天市场表现、盘后重要公告、国内外消息，以及后续值得关注的事件。
3. **核对某条消息**：用户从摘要直接打开原文，核对发布时间、具体措辞或数字。
4. **补看历史内容**：用户在网页选择日期、期次，查看此前简报及更正记录。

### 3.3 首版目标

- 用户打开卡片后，可以在约一分钟内知道本期最重要的三到五件事。
- 用户无须自行搜索，即可从每条信息进入对应原文。
- 桌宠以低打扰的方式提醒更新，用户能够关闭提醒并继续主动查看。
- 网页与桌宠呈现同一期、同一版本的内容。

以上阅读时长和条目数量是设计目标，需要通过样稿与试用校准。

## 5. 信息结构与简报内容

### 5.1 单期简报

| 区域 | 内容要求 |
| --- | --- |
| 标题区 | 日期、午间/晚间、覆盖市场、发布时间、信息截止时间、版本 |
| 一句话概览 | 以可核对的市场表现概括本期，避免情绪化判断 |
| 核心重点 | 默认三到五条；不足时如实展示，不补入低质量消息 |
| 市场概况 | 选定指数表现、成交情况、行业变化；逐项提供数据来源与时间口径 |
| 国内动态 | 政策、经济数据、公司公告及重要事件，按市场相关性筛选 |
| 国际动态 | 海外政策、经济数据、公司事件与其他市场相关事件，保留原始来源 |
| 后续关注 | 已公布日程、后续公告或数据；区分确定日程与待确认事项 |
| 更正记录 | 展示本期内容的修订时间、原因与涉及条目 |

同一事件出现在多个来源时合并为一条，并将来源挂在对应事实下。国内、国际分类可作为标签，避免同一事件在多个区域重复展示。

### 5.2 午间与晚间的区别

- **午间**：聚焦当日上午市场表现、热点变化与截至内容截止时间的重要消息。
- **晚间**：包含全天市场回顾及截止时点已发布的盘后、国内外信息。用一个晚间版本承载收盘复盘与晚间消息更新，首版不增加第三次常规推送。
- 海外市场未结束时，必须写“截至某时”，不得写为已收盘。
- 国内市场休市时，界面明确显示休市；是否提供新闻专刊待定，不自动生成虚构的市场复盘。

### 5.3 单条信息结构

每条信息至少包含：

1. 标题与简洁事实摘要。
2. 事件发生时间（可确认时）、原文发布时间，以及时区。
3. 来源机构、原文标题、具体原文链接。
4. 对应事实的证据片段或文档页码，供网页版展开核对。
5. 原文核对状态、最近核对时间。
6. 可选的影响分析与后续关注，独立于事实区。
7. 更正与替代关系，例如“此条已由后续公告更新”。

摘要含有多个独立事实时，每个事实都要有对应证据。不得在一段混合多个结论后只附一条无法覆盖全部内容的链接。

## 6. 真实性、来源与发布规则

### 6.1 对用户的承诺边界

用户要求所有信息确认真实性并提供原始链接。执行标准为：**发布的事实均有可访问的原始依据，经过原文核对；无法确认的内容不进入正式简报。**

外部机构或媒体也可能出错或修订，因此“已核对原文”只表示摘要与所列来源一致，不代表系统已独立证明现实世界中的每一项陈述。产品不使用“绝对真实”“百分之百准确”等标识。

### 6.2 来源优先级

| 信息类型 | 优先证据 | 发布要求 |
| --- | --- | --- |
| 政策与监管 | 发布机构正式文件、公告与发布会实录 | 区分征求意见、正式发布、生效与实施时间 |
| 公司信息 | 交易所披露文件、公司公告与投资者关系页面 | 数字、主体、报告期与公告状态一致 |
| 经济数据 | 原始统计发布机构 | 保留单位、统计周期、初值/修订值等口径 |
| 行情 | 交易所或具备所需使用权限的数据服务 | 标明对应市场、时间、延迟状态和统计口径 |
| 新闻事件 | 当事机构公开材料或具有明确采编来源的原创报道 | 事实表述必须与证据强度相匹配 |

官方披露类事实优先回到正式文件。独家报道需要注明“某媒体报道”，不得改写成已获当事方确认。涉及匿名消息、无法核实的爆料、截图传闻与存在重大冲突的说法，首版不收入正式简报。

多个网站转载同一篇稿件，只算一个来源。涉及需要交叉核验的重大新闻，核对独立来源，不能以转载数量替代核验。

候选官方入口（仅用于来源发现；实际简报必须链接具体原文）：

- [上交所公司公告](https://star.sse.com.cn/disclosure/listedinfo/announcement/)
- [深交所信息披露](https://www.szse.cn/disclosure/index.html)
- [美联储新闻发布](https://www.federalreserve.gov/newsevents/pressreleases.htm)

完整来源清单、获取方式、覆盖范围、稳定性与使用权限，需要在接入前单独验证。公开可阅读不自动等于可批量采集或再分发。

### 6.3 核验流水线

**发现候选消息 → 获取原文 → 校验来源身份与日期 → 事件去重 → 建立事实与证据对应关系 → 基于证据生成摘要 → 逐项复核 → 发布。**

- 搜索结果的标题和摘要只用于发现线索，不能直接作为发布证据。
- 核对正文，不以链接能打开或返回成功状态替代内容核验。
- 模型只能基于已获取的证据整理内容，不能自行补齐缺失数字、原因或链接。
- 数值检查覆盖金额、币种、百分比与百分点、正负号、单位、时间范围和比较基准。
- 计算得出的数据注明计算方法和输入来源；输入不完整时不计算。
- 涨跌原因没有充分证据时不强行归因；同时发生的新闻不能直接写为因果关系。
- 网页与 PDF 中的内容属于待核验资料，不得作为操作指令执行。
- 不能确认的条目进入复核队列；无人复核时跳过，不阻塞其他合格内容发布。

### 6.4 链接与证据规则

- 原文链接必须由实际采集结果取得并验证，禁止模型编造或猜测路径。
- 优先直达具体文章、公告页面或 PDF；不以机构首页、搜索页、转载聚合页替代。
- 为每条证据保存来源机构、原文标题、最终链接、发布时间、核对时间及必要证据片段。
- 原始材料为外文时，中文摘要保留外文原文链接；翻译不得改变条件、语气和不确定性。
- 付费或登录来源明确标识访问限制；首版优先选择用户可直接访问的来源。
- 历史链接失效时标明失效状态；保留原核对记录，找到同机构的原始存档时补充链接。

### 6.5 不完整、冲突与更正

- 核验未完成：不发布该条事实。
- 来源冲突：暂缓相关结论，进入复核队列；不得让模型自行选一个结论。
- 数据接口异常：缺失项显示“暂不可用”，不以过期数据冒充当前数据。
- 生成或核验延迟：显示本期更新状态与上一期日期，不把旧期内容标为新期。
- 发布后发现错误：立即修订或撤回对应条目，保留旧版本与更正说明。
- 重要更正同步到桌面端，明确属于更正；已关闭普通提醒的用户在下次打开卡片时仍能看到更正标识。

## 7. 网页端需求

### 7.1 首页与下载

- 首屏可阅读最新一期简报的重点，并显示日期与信息截止时间。
- 展示小猪形象、核心功能与支持的平台。
- 明确区分“在网页阅读”和“下载桌宠”两个入口。
- 下载入口显示平台、版本与更新说明；尚未支持的平台明确标注。
- 没有可发布简报时显示真实的等待或异常状态，不填充貌似真实的示例新闻。

### 7.2 简报详情

- 显示完整简报，事实、分析与来源在视觉上分开。
- 每条信息附近都有“查看原文”，不把所有来源只堆在页尾。
- 可展开证据片段、原文标题和相关信息。
- 桌宠打开详情时定位到相应条目；网页版仍能独立访问与分享具体期次。

### 7.3 历史与更正

- 按日期与午间/晚间筛选。
- 历史内容显示当时的信息截止时间，防止误认为当前行情。
- 默认呈现最新修订版本，允许查看更正说明。
- 已撤回条目保留说明与时间，不继续作为有效事实展示。

## 8. 桌面端需求

### 8.1 基础行为

- 启动后显示小猪，支持拖动并记住位置；屏幕变化后仍能找回桌宠。
- 单击打开或收起摘要卡片；拖动操作不误触打开。
- 卡片跟随桌宠位置调整，避免超出屏幕。
- 提供打开网页版、提醒设置、隐藏与退出入口；隐藏后有明确恢复方式。
- 置顶与开机启动提供用户设置，默认行为在首个平台原型中确认。
- 桌宠空闲时以轻微动作维持陪伴感，避免持续大幅移动影响工作。

### 8.2 摘要卡片

卡片默认展示顺序：

1. 期次、日期、信息截止时间与更新状态。
2. 一句话概览。
3. 三到五条重点，每条包含简洁摘要、来源、发布时间和原文入口。
4. “阅读完整简报”入口。

卡片的“查看原文”直接打开该条原始来源；“阅读完整简报”打开产品网页。桌面端不得只提供跳转产品网站、让用户继续寻找来源。

### 8.3 提醒与异常

- 新一期发布后，小猪通过一次轻微动作和短气泡提示，支持关闭提醒。
- 同一期内容不重复普通提醒；重要更正作为独立状态处理。
- 用户点击后标记已读，网页与桌面端使用同一期次和版本。
- 断网时可显示已缓存内容，但明确标注缓存时间与离线状态。
- 免打扰期间保留未读状态，不反复动画或弹出系统通知。
- 常规新闻不逐条弹窗；突发事件提醒作为后续扩展。

## 9. 小猪形象与动作

### 9.1 唯一参考基准

用户于 2026-11-02 提供的小猪图片为当前默认形象基准：

![用户提供的小猪参考图](assets/reference/pig-reference.png)

本地文件：`assets/reference/pig-reference.png`。此文件保留原始参考图，用于后续角色设计；它本身尚不是可直接上线的动画素材。

### 9.2 必须保留的视觉特征

- 肥肥的横向圆润身体，比例略笨拙、可爱。
- 浅桃色身体，玫红色耳部曲线与粉红色鼻子。
- 黑色豆豆眼、黑色鼻孔、短腿和卷尾巴。
- 扁平色块、轻微不规则的手绘轮廓，保留参考图的朴拙感。
- 尺寸缩小后仍能认出鼻子、眼睛和身体轮廓。

用户希望带一点“小猪储蓄罐”的感觉。优先通过圆润体态、小硬币或存放简报道具表达；是否增加投币口、是否使用陶瓷质感，等视觉稿确认，不直接改成写实或立体角色。

桌面素材使用透明背景，网页展示可搭配浅色背景。原始图片完整保存在 assets/reference；三张初版透明 PNG 保存在 assets/pig。当前抠图边缘仍需精修，正式角色动画尚未制作。

### 9.3 P0 动作与信息状态

| 状态 | 建议动作 | 对用户传达的含义 |
| --- | --- | --- |
| 待机 | 轻微呼吸、眨眼、耳朵轻动 | 正常陪伴 |
| 整理资料 | 低头看小纸条或翻简报 | 本期正在更新，尚未发布 |
| 简报送达 | 拿出一张小简报，轻轻晃动 | 新一期已可阅读 |
| 点击回应 | 轻微弹一下、耳朵动一下 | 操作已响应 |
| 休息/免打扰 | 趴下或闭眼 | 提醒暂停，仍可主动查看 |
| 重要更正 | 举起更正标识或小纸条 | 已发布信息发生修订 |

用户已确认三种行情表情纳入首版：开心对应行情好，委屈对应行情坏，思考对应难以预料。初版手动切换用于预览；自动切换需另行明确市场、指标、观察周期与阈值，并与对应数据一起展示。数据不足时保持中性，不把采集失败当作行情难以预料。表情仅描述已观察状态，不表达未来走势预测或买卖建议。

### 9.4 自定义路线

- P0：一个完整默认小猪，优先保证动作、卡片与提醒体验。
- P1：改名、配饰、颜色主题与大小设置。
- 后续：官方其他角色、用户上传角色及动画适配。

用户尚未确定产品名称、小猪名称、最终画风细化与动画制作方式。

## 10. 内容系统与数据要求

网页与桌面端共用一套简报数据与版本。内容集中生成和核验后分发，避免每台桌宠自行生成不同事实。

最低需要保存以下对象：

| 对象 | 关键内容 |
| --- | --- |
| 来源 | 发布机构、类型、可信域名、获取方式、访问与使用条件 |
| 原始材料 | 标题、链接、发布时间、采集时间、正文或必要证据、内容标识 |
| 事实条目 | 主体、时间、事实文本、引用证据、核验状态与失败原因 |
| 分析条目 | 分析文本、依赖事实、不确定性与分析标识 |
| 简报 | 日期、期次、覆盖市场、截止时间、发布时间、状态、版本、条目列表 |
| 更正 | 旧版本、新版本、涉及事实、原因、时间、提醒级别 |
| 本地偏好 | 桌宠位置、显示与提醒设置、已读期次、缓存时间 |

简报状态至少包括：准备中、核验中、已发布、已修订、已撤回、更新异常。只有通过核验的版本能够作为正式简报分发。

原始正文与证据的保存范围依来源使用条件确定；用户偏好优先保存在本地。后续如增加持仓或账号同步，需单独明确数据用途、保存与删除方式。

## 11. 首版验收标准

| 编号 | 验收内容 | 通过条件 |
| --- | --- | --- |
| A01 | 网页可用 | 未安装桌宠时仍能阅读最新与历史简报 |
| A02 | 下载与运行 | 至少一个已确认平台可以下载安装、启动、隐藏恢复及退出 |
| A03 | 小猪交互 | 显示参考图方向的小猪；拖动、点击、打开卡片不互相误触 |
| A04 | 摘要阅读 | 卡片显示期次与截止时间，可查看重点并打开完整简报 |
| A05 | 原始链接覆盖 | 发布内容中的每条事实均有直接支持它的具体原文链接；缺少者被拦截 |
| A06 | 原文一致性 | 对验收样本逐条比对正文，主体、数字、单位、时间与条件一致 |
| A07 | 无法核实的内容 | 注入传闻、仅有搜索摘要或打不开正文的条目，不进入正式简报 |
| A08 | 新闻去重 | 多次转载同一消息不会生成多条重点或被计为多个独立来源 |
| A09 | 事实与分析 | 分析明确标识且有依赖事实；不把相关性写成确定因果 |
| A10 | 时效性 | 旧闻、修订数据、海外时区与未收盘状态得到正确标识 |
| A11 | 失败降级 | 采集失败或核验延迟时说明状态，不伪造新一期或缺失数据 |
| A12 | 更正同步 | 修订可追溯，网页与桌面显示同一最新版本，重要更正可见 |
| A13 | 提醒控制 | 每期普通提醒至多一次，支持关闭与免打扰 |
| A14 | 离线内容 | 缓存内容明确标记离线及时间，不冒充最新信息 |

验收覆盖正常发布及故障样本。事实来源覆盖率要求为 100%；该指标代表产品发布规则，不代表对外部事实绝对无误的承诺。

## 12. 验证指标

首轮试用重点观察以下指标，具体目标在获得试用基线后设定：

- 发布事实的原始链接覆盖率与抽查一致率。
- 错误、撤回、更正数量及更正同步耗时。
- 午间、晚间简报按计划发布的比例与失败原因。
- 摘要卡片打开率、完整简报阅读率与原文访问情况。
- 连续使用天数、提醒关闭率、隐藏/退出原因。
- 用户反馈：是否节省查阅时间、是否知道消息依据、是否愿意每天继续看。

原文点击率单独用于理解用户行为，不作为内容真实性的替代指标。

## 13. 实施顺序与下一步

1. **内容样稿与核验样例**：用真实原文制作午间、晚间各一份样稿，验证事实、分析、来源的展示方式。
2. **视觉与交互原型**：依据当前小猪参考图，制作透明角色稿、基础动作示意和摘要卡片；同时确认首发桌面平台。
3. **网页阅读闭环**：完成最新、详情、来源、历史及更正页面，能够独立使用。
4. **内容生产闭环**：接入有限数量的合格来源，跑通采集、核验、发布和异常处理。
5. **桌宠闭环**：接入同一份简报，实现常驻、拖动、点击卡片、提醒与网页版跳转。
6. **小范围试用**：验证阅读价值、核验质量和提醒频率，再决定个性化与其他角色的优先级。
